# Examples

## 超时

差：用户 A 在接口 X 上传 PDF 超时，加个 60s timeout。

好：

```markdown
宿主：通用服务 — 各类上传/导入任务
问题类别：长耗时 IO 没有按任务类型设置超时与重试
不变量：每类任务都有明确超时、重试次数和失败语义
变体：视频上传；大 JSON 导入
机制：按任务类型配置超时/重试，统一错误出口
变化点：PDF=60s、视频=180s
这个 case：PDF 上传使用长任务配置
验收：换视频导入仍走同一超时表
不做：自研任务调度平台
```

## 轻量档 / 跳过

跳过：分页 `offset` 少减 1，直接改，不套模板（单点缺陷，不新增分支）。

轻量档：某接口重试次数写成 0，改成读已有的重试配置。

```markdown
问题类别：重试参数绕过统一配置
机制：所有出网调用从同一份重试配置取值
这个 case：该接口接回配置，删掉硬编码 0
```

## 校验

差：这个字段不能为空，在 handler 里加一行判断。

好：入口统一校验契约；这个字段是契约里的一条规则。

## 兼容

差：`if (userId === "vip-123")` 走新逻辑。

好：差异用规则/策略表达；当前用户是规则表里的一条。

## 降级

差：这个模型挂了，写死返回固定文案。

好：按能力路由 + 失败策略；当前模型是路由表里的一个实现。

## 宿主边界（升层停在领域）

差：多租户报表服务里，用户按部门全称筛选查不到数据（索引里存的是部门编码），机制写成「部门名转部门编码」，验收只换全称和简称两种写法。

好：

```markdown
宿主：通用服务 — 多租户结构化检索
问题类别：过滤条件的表面形式与索引里的标识形式不一致
不变量：硬过滤只用解析后的标识；解析失败或滤空时先按索引字段做字面回退，不直接返回空
变体：同一租户里全称/简称；另一个租户里产品线名对 SKU 前缀
机制：抽出候选 → 展开别名 → 解析为索引标识 → 过滤 → 滤空字面回退 → 仍空才报无结果
变化点：标识解析器、按租户加载的别名表、参与过滤的字段
这个 case：部门标识解析器 + 该租户的别名表
验收：换一个没有部门概念的租户，同一套主路径仍成立
不做：把某一种标识形式写成服务唯一实现
```

判定：领域词在「变化点 / 这个 case」里 → 对；领域词在「机制」里 → 差。
